# Outputs Directory

This directory stores exported evaluation data from Jupyter notebooks.

---

## Export Formats

Notebooks export data in multiple formats:

### Markdown (.md)
- Matches original template format exactly
- Suitable for inclusion in thesis/papers
- Human-readable documentation
- Example: `session-log-musicgen-2025-10-10.md`

### CSV (.csv)
- Tabular data for statistical analysis
- Can be imported to R, Python pandas, Excel
- Ideal for quantitative score aggregation
- Example: `quantitative-musicgen-2025-10-10.csv`

### JSON (.json)
- Structured data export
- Programmatic access to evaluation data
- Machine-readable format
- Example: `session-data-2025-10-10.json`

---

## File Naming Convention

Templates use this naming pattern:

```
{template}-{system}-{date}.{format}
```

**Examples:**
- `session-log-musicgen-2025-10-10.md`
- `quantitative-riffusion-2025-10-15.csv`
- `critical-incident-ddsp-vst-2025-10-12.md`
- `comparative-analysis-2025-10-20.md`

---

## Usage

### Generating Exports

Files in this directory are generated by running notebooks and executing export cells:

```python
# In notebook
export_to_markdown(session_data, 'outputs/session-log-musicgen-2025-10-10.md')
export_to_csv(session_data, 'outputs/session-log-musicgen-2025-10-10.csv')
export_to_json(session_data, 'outputs/session-log-musicgen-2025-10-10.json')
```

### Aggregating Data

Use helper functions to aggregate multiple exports:

```python
from utils.helpers import aggregate_sessions, aggregate_quantitative

# Aggregate all session logs
summary = aggregate_sessions('outputs/session-log-*.md')

# Aggregate quantitative scores
scores = aggregate_quantitative('outputs/quantitative-*.csv')
```

## Git Ignore

**Note:** This directory is git-ignored except for `README.md` and `.gitkeep`

Export files are excluded from version control to:
- Avoid committing potentially large files
- Prevent accidental sharing of unpublished research data
- Keep repository focused on code/templates

To include exports in version control, modify `.gitignore` in the repository root.

---

## Backup Recommendations

Since exports are not version controlled, consider:

1. **Regular backups** - Copy `outputs/` to secure location
2. **Cloud sync** - Use Dropbox/OneDrive/Google Drive
3. **Study repository** - Create separate git repo for evaluation data
4. **Archive** - Compress and archive completed evaluations

## Cleanup

To remove all generated files:

```bash
# Remove all markdown exports
rm outputs/*.md

# Remove all CSV exports
rm outputs/*.csv

# Remove all JSON exports
rm outputs/*.json

# Remove everything except README and .gitkeep
find outputs/ -type f ! -name 'README.md' ! -name '.gitkeep' -delete
```
